# Questão 06 — Comportamento e Precedência dos Incrementos

## Pergunta

O comportamento de incrementos prefixados e pós-fixados (`++x` e `x++`) é uma fonte frequente de erros sutis na Linguagem C. Analise os dois trechos de código independentes abaixo e responda:

```c
// Trecho A
int n = 5;
int x = ++n;
printf("Trecho A: n = %d, x = %d\n", n, x);

// Trecho B
int m = 5;
int y = m++;
printf("Trecho B: m = %d, y = %d\n", m, y);
```

a) Explique a diferença de fluxo e atribuição que ocorre entre o operador prefixado (`++n`) e o pós-fixado (`m++`). Quais serão os valores impressos na tela por cada trecho?

b) Um programador júnior tentou imprimir uma variável em `printf()` modificando-a múltiplas vezes de forma sequencial na mesma chamada: `printf("%d\t%d\t%d\n", n, n+1, n++);`. Explique por que essa instrução pode gerar resultados inconsistentes e imprevisíveis dependendo do compilador adotado (comportamento indefinido).

---

## Resposta

### a)

Os dois operadores incrementam a variável. A diferença está em **quando** isso acontece em relação ao uso do valor.

| Forma | Ordem | Valor que a expressão devolve |
|---|---|---|
| `++n` (prefixado) | incrementa primeiro, depois usa | o valor **novo** |
| `m++` (pós-fixado) | usa primeiro, depois incrementa | o valor **antigo** |

**Trecho A:**

```
n vale 5
1) n é incrementado       → n = 6
2) a expressão devolve 6  → x = 6
```

Saída: `Trecho A: n = 6, x = 6`

**Trecho B:**

```
m vale 5
1) a expressão devolve 5  → y = 5
2) m é incrementado       → m = 6
```

Saída: `Trecho B: m = 6, y = 5`

**Resumindo:** nos dois casos a variável original termina valendo 6. O que muda é o valor que foi *capturado* na hora da atribuição — `x` ficou com 6, `y` ficou com 5.

Uma observação prática: quando o incremento está sozinho numa linha (`n++;` ou `++n;`), tanto faz qual forma usar. O valor devolvido é jogado fora de qualquer jeito. A diferença só importa quando esse valor é aproveitado por outra operação.

---

### b)

```c
printf("%d\t%d\t%d\n", n, n+1, n++);
```

Essa linha tem **comportamento indefinido**, e por dois motivos que se somam.

**Primeiro: o C não define a ordem de avaliação dos argumentos de uma função.**

O padrão exige que todos os argumentos sejam avaliados antes da chamada, mas deixa a ordem em aberto de propósito. Cada compilador escolhe o que for mais conveniente para a arquitetura alvo.

O GCC em x86 costuma avaliar da direita para a esquerda, por causa de como os argumentos são empilhados. Outros compiladores, ou o mesmo compilador com otimizações ligadas, podem fazer diferente.

**Segundo: a variável é lida e modificada na mesma expressão.**

O `n` aparece sendo lido nos dois primeiros argumentos e sendo alterado no terceiro (`n++`), sem nenhum ponto de sequência separando essas ações. O padrão diz explicitamente que isso é comportamento indefinido.

**O resultado prático**, começando com `n = 5`:

| Se avaliar... | Sai |
|---|---|
| da direita para a esquerda | `6  7  5` |
| da esquerda para a direita | `5  6  5` |

O mesmo código-fonte, dois resultados diferentes.

E cabe um alerta: "comportamento indefinido" em C é mais sério do que "resultado imprevisível". Significa que o compilador está liberado para fazer qualquer coisa — inclusive descartar trechos de código durante a otimização, partindo do princípio de que aquela situação nunca deveria acontecer.

**Como escrever isso corretamente:**

```c
int n = 5;
printf("%d\t%d\t%d\n", n, n + 1, n + 2);
n += 3;
```

A regra que evita o problema: dentro de uma mesma expressão, nunca modifique uma variável mais de uma vez, nem a modifique e leia ao mesmo tempo. Compiladores modernos avisam sobre isso — basta compilar com `-Wall`.
